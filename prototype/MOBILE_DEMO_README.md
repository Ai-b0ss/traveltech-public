# О!дин запрос: автономный мобильный UI-прототип

Автор исходного прототипа — **Илья (@f0ut324)**, подготовка с помощью AI.
В рамках [#46](https://github.com/Ai-b0ss/traveltech/issues/46) уже готовый HTML
перенесён без изменения дизайна и логики в
[`mobile_odin_zapros_20261024.html`](mobile_odin_zapros_20261024.html).

Это самостоятельная демонстрация интерфейса. Она не подключена к серверу
TravelTech и не является реализацией полноценного AI-агента.

## Как открыть

Скачайте репозиторий и дважды щёлкните по
`prototype/mobile_odin_zapros_20261024.html` либо откройте его через меню браузера
«Открыть файл». **Сервер, установка зависимостей и интернет не нужны.**
Для мобильного вида включите в инструментах разработчика ширину около **390 px**.

## Что работает

- Три карточки: «В самый раз», «Больше экономии», «Без лишних забот».
- Выбор варианта обновляет сумму, отель, маршрут и условия в интерфейсе.
- Сравнение трёх вариантов в отдельном окне.
- Редактирование дат и бюджета; быстрые команды «Подешевле», «На 2 дня позже»,
  «Всё включено».
- Маршрут с перелётами туда/обратно, трансферами и проживанием.
- Окно проверки заказа и экран демонстрационного успеха.
- На телефоне — закреплённое поле ввода и история диалога в шторке.

## Что не работает и что имитируется

- AI-модель не подключена: распознаются только несколько заранее заданных команд.
- Нет поиска реальных рейсов, проверки доступности отелей и актуальных тарифов.
- Нет backend-сессии, сохранения в SQLite или восстановления состояния после
  перезагрузки страницы.
- Нет реального бронирования, оплаты или отправки заказа на backend.
- ID демонстрационного заказа фиксированный: `О!–2026–001`; уникальные заказы
  не создаются.

**Источник всех цен, рейсов, отелей и условий — `MOCK`**:
синтетический массив `const plans = [...]` внутри HTML.
Это не реальные брони и не предложения, доступные к покупке.

## Ограничения демо

- Москва → ОАЭ: Дубай, Шарджа, Рас-эль-Хайма.
- 2 взрослых + ребёнок 4 лет.
- Ноябрь 2026 года, 7 ночей; начальные даты — 12–19 ноября.
- Форма разрешает начало поездки с 1 по 23 ноября.
- Цены фиксированы: **142 500 ₽**, **118 000 ₽**, **189 000 ₽** за весь сценарий.
  При переносе даты они **не пересчитываются**. Изменение бюджета само по себе
  тоже не получает новые тарифы от поставщика.
- Страховка в этом UI задана как отдельная MOCK-строка **2 000 ₽**.
- Смена города вылета, состава гостей, числа ночей и произвольные новые условия
  не поддерживаются текущим каталогом.

## Какие данные ждём от Backend

Это **запрос к Игорю в [#43](https://github.com/Ai-b0ss/traveltech/issues/43)**
для одной будущей карточки, **не утверждённый API-контракт**. Интеграция относится
к отдельной задаче [#47](https://github.com/Ai-b0ss/traveltech/issues/47).
Ни HTTP, ни SQLite, ни `experimental/` этим прототипом не меняются.

| Какие данные нужны UI | Для чего |
|---|---|
| `trip_id`, `revision` | Связать карточку с поездкой и её версией |
| `destination` | Показать направление |
| `start_date`, `end_date` | Показать даты поездки |
| `travellers` | Показать взрослых и возраста детей |
| `hotel.name`, `hotel.checkin`, цена отеля (`hotel.price` в формулировке запроса) | Подпись, заезд и строка стоимости проживания |
| `transport.departure_at`, `transport.arrival_at`, цена транспорта (`transport.price`) | Время пути с часовыми поясами и стоимость |
| Длительность трансфера (`transfer.duration`), цена (`transfer.price`) | Время до отеля и строка стоимости трансфера |
| `total_amount`, `currency` | Итог за согласованный состав поездки и валюта |
| `source_mode` | Явно показать `MOCK` / другой согласованный режим источника |
| `warnings` | Показать неизвестные цены, ограничения и конфликты |

В опубликованном предложении Игоря
([PR #66](https://github.com/Ai-b0ss/traveltech/pull/66),
[описание TripPlan v0](https://github.com/Ai-b0ss/traveltech/blob/feat/issue-43-trip-plan-v0/docs/contracts/TRIP_PLAN_V0.md))
цены компонентов уже названы **`amount`**, а режим источника передаётся у каждого
компонента. Отдельные поля `*.price` или новый параллельный JSON не требуются:
для следующего шага нужно согласовать отображение существующих `amount` и
`source_mode` в UI.

Для согласования остаются длительность трансфера (единица — минуты), охват его
цены (одна сторона или обе) и условия/локальное время заселения, если UI должен
проверять состыковки. Обратные времена рейсов и `hotel.checkout` полезны для
полного маршрута и уже предусмотрены предложением.

Предложение TripPlan v0 содержит `insurance.amount: null` и предупреждение
`PRICE_UNKNOWN`, итог известных строк **140 500 ₽**. Будущий UI должен показать
неизвестную страховку явно, не заменять её нулём или локальными 2 000 ₽ из этого
HTML. Формат денег, обязательность полей, неизвестные значения и поведение после
смены дат согласуются в #43; окончательный источник формата — согласованный
TripPlan, а не автономный макет.

## Проверка в браузере

1. Откройте HTML заново. Убедитесь, что доступны три варианта и начальный итог
   равен **142 500 ₽**.
2. Выберите «Больше экономии»: итог должен стать **118 000 ₽**.
3. Нажмите «На 2 дня позже»: даты меняются с **12–19** на **14–21 ноября**,
   выбранный вариант сохраняется, сумма остаётся **118 000 ₽**.
4. Откройте сравнение; проверьте наличие трёх вариантов и закройте окно.
5. Через «Изменить» откройте параметры, проверьте поля дат и бюджета.
6. Нажмите «К оформлению» / «Оформить», затем «Оформить демо-поездку».
   Появляется «Поездка собрана!», а во вкладке Network нет запроса заказа.
7. Повторите сценарий при ширине **390 px**. Поле ввода, быстрые команды и кнопка
   оформления доступны; историю можно открыть и закрыть без возврата наверх.
8. Проверьте Console: JS-ошибок нет. В Network не должно быть HTTP(S)-запросов
   самого автономного HTML.

Эти шаги проверяют только UI на MOCK-данных. Они не являются полной приёмкой
конкурсных A04/A06/A07 или доказательством работы AI/API.
