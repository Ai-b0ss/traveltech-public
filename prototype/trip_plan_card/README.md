# Одна карточка TripPlan v0 · #47

Локальная реализация ограниченного этапа [#47](https://github.com/Ai-b0ss/traveltech/issues/47)
родительской задачи [#33](https://github.com/Ai-b0ss/traveltech/issues/33).
Карточка показывает состав поездки из JSON. Все цены и рейсы примера — **MOCK**.

## Статус интеграции

- `experimental/trip_plan_card.js` экспортирует чистую функцию `renderTripPlanCard(plan)`.
  Она возвращает HTML, экранирует входные строки, не изменяет объект и не делает запросов.
- `index.html` и `preview.js` здесь — отдельная страница проверки этой функции.
  Она читает только соседний статический `trip_plan_v0.json`.
- Используются цвета, шрифты и базовые стили существующего UI. Новые стили компонента
  ограничены классами `trip-plan-*`.
- **API не подключён.** Карточка не отображается в основном гостиничном поиске,
  не привязана к текущей сессии и не обновляется при изменении её бюджета или дат.
  `/api/commit`, backend, SQLite и существующие `index.html`, `full.js`, `ui.js` не изменены.
- Отдельная render-функция и проверка fixture предусмотрены шагом 3 задачи #47,
  пока backend не отдаёт TripPlan. Это не завершение #33 или этапа пересборки #48.

## Источник данных и разрешённый объём

`trip_plan_v0.json` — побайтовая копия
[`docs/contracts/trip_plan_v0.json` из PR #66](https://github.com/Ai-b0ss/traveltech/blob/14e2e0052d46c3d1794f8d8eefbee43152b81850/docs/contracts/trip_plan_v0.json).
Commit источника: `14e2e0052d46c3d1794f8d8eefbee43152b81850`.
SHA-256: `3e34bb439333942640bd4ac85e948491234a8159dec8f1d8f6e632a44340a7e7`.
Это fixture для отображения, не новая версия контракта и не копия серверного состояния.

Основание — [согласование Игоря для ограниченного #47](https://github.com/Ai-b0ss/traveltech/issues/47#issuecomment-6388799773).
Весь контракт #66 по-прежнему требует отдельного ревью. Поля не добавлены и не переименованы:

- Используются `hotel.amount`, `transport.amount`, `transfer.amount` и существующие
  `source_mode`/`provider` каждого компонента; новое поле `price` не вводится.
- Перелёт туда и обратно — одна сумма 54 000 ₽, отель — 81 000 ₽.
- 5 500 ₽ — только аэропорт → отель. Обратный трансфер не включён.
- Длительность трансфера и время заселения отсутствуют: «нет данных».
  Стыковка требует проверки; статус успешной проверки не придумывается.
- `insurance.amount: null` отображается как «Цена неизвестна» вместе с входным
  предупреждением `PRICE_UNKNOWN`. Ноль или 2 000 ₽ не подставляются.
- `total_amount: "140500.00"` показывается как **сумма известных компонентов**,
  с явным пояснением, что это не окончательная цена поездки.

Функция отображает полученный `total_amount`, не складывает цены во фронтенде.
При неизвестной обязательной цене или разных валютах сумма скрывается до перепроверки.
Времена рейсов сохраняют локальное время и UTC-смещение из JSON независимо от часового
пояса браузера. У неизвестных дат, источников, версии и сумм нет выдуманных значений.

## Как посмотреть

Из корня репозитория:

```powershell
python -m http.server 8816 --bind 127.0.0.1
```

Открыть <http://127.0.0.1:8816/prototype/trip_plan_card/index.html>.
В отличие от автономного HTML из #46, этой странице нужен локальный сервер для чтения JSON.
Двойной клик по HTML может блокировать `fetch` в браузере; тогда появится инструкция об ошибке.
Остановить сервер: `Ctrl+C`.

## Проверка вручную

1. Открыть страницу на ширине 1365 px, затем 390 px. Должна быть **одна** карточка
   Москва → Дубай, даты 12.11.2026–19.11.2026, 2 взрослых и ребёнок 4 лет.
2. Проверить цены 54 000 / 5 500 / 81 000 ₽ и сумму известных компонентов **140 500 ₽**.
   У страховки — «Цена неизвестна», в предупреждении — `PRICE_UNKNOWN`.
3. Проверить подписи: только аэропорт → отель, обратный трансфер не включён;
   длительность и время заселения — «нет данных».
4. Проверить местное время вылета 10:00 UTC+03:00 и прилёта 16:30 UTC+04:00,
   а также обратные рейсы. В другом часовом поясе браузера часы должны остаться прежними.
5. Прокрутить всю карточку. Горизонтальной прокрутки нет, подписи и суммы не обрезаны;
   ссылки под карточкой доступны мышью, касанием и клавишей Tab.
6. В DevTools убедиться: нет JS-ошибок, запросов к `/api/*`, внешним поставщикам,
   отправки данных или бронирований. Есть только GET локальных файлов.

## Автоматическая проверка

```powershell
node --test tests/trip_plan_card.test.cjs
python scripts/check_local.py
git diff --check
```

Новые 6 тестов входят в `check_local.py`, если установлен Node.js. Они проверяют
точный fixture, отсутствие мутации входа, неизвестные и некорректные значения,
явный ноль, разные валюты, часовые смещения и экранирование HTML.

Браузерная проверка требует Node.js, доступный пакет `playwright` и Edge либо Chrome:

```powershell
node tests/trip_plan_card.browser.cjs
# Если вместо Edge используется Chrome:
$env:TRAVELTECH_BROWSER_CHANNEL = 'chrome'
node tests/trip_plan_card.browser.cjs
```

Скрипт сам поднимает временный сервер только для файлов примера, проверяет 390/1365 px,
пустые данные, HTML-инъекцию, неизвестный итог и нечитаемый JSON; внешние и backend-запросы
запрещены. Он обновляет снимки `evidence/after-*.png`.

Проверено локально 24.10.2026, Windows, Chrome 156.0.8078.47, Python 3.13,
Node.js 24.22.1, от базы `5fdf63f63cda30c7fdf39c8b80383bc38e126336`:

- `check_local.py`: 16 Python-тестов и 26 подтестов, 6 новых Node-тестов,
  сортировка, синтаксис и HTTP smoke — PASS; inference/public API calls = 0.
- `trip_plan_card.browser.cjs`: 10 групп проверок на двух ширинах — PASS.
  Включена проверка с часовым поясом браузера America/Los_Angeles.
- Отдельный проход существующего UI на 1365 и 390 px: ввод, три отеля,
  сравнение двух отелей, Preview → подтверждение бюджета 20 000 ₽,

  ошибок `/api/*` или внешних запросов. Сняты `before-hotel-*.png`.
