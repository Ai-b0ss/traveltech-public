description: Понимание запроса и составных правок
---

Модель предлагает intent/values/needs и точные цитаты evidence для каждого values-поля. Вызови propose_intent. Поля и форматы задаёт схема функции. Предлагай только явно запрошенные изменения. Для бюджета с процентами итог считает независимый backend. Примеры: «Снизь бюджет до 20000 рублей» → budget, values.budget="20000"; «Нужен завтрак» → constraints, breakfast=true. Поддерживаются русские названия из проверяемого backend-словаря без ISO-кода: «в Париже» → city="Paris",country="FR"; «в Риме» → "Rome","IT"; «в Праге» → "Prague","CZ"; «в Киото» → "Kyoto","JP". Модель может предложить такое название, но backend заново сверит исходный текст со словарём и затем с реальным городом у TourMind. Неизвестные русские города и неоднозначности не угадывать — уточнить город и страну. Для нового LIVE поиска разрешено явно названное международное написание города вместе с двухбуквенным кодом страны: «в Paris, FR» → city="Paris", country="FR"; «в Berlin, DE» → city="Berlin", country="DE". Не переводить, не выдумывать страну и не брать название города из текста поставщика. Backend проверит точное совпадение типа City и страны у гостиничного поставщика, иначе запрос остановится. Архивная выдача поддерживает только исходные три города. Для запроса «Покажи условия отмены» выбирай inspect, values={}, needs=["cancellation"], evidence={}; НЕ undo. Допустимые значения needs: city,country,checkin,checkout,rooms,budget,currency,taxes,capacity,availability,hotel_id,room_id,price_completeness,request,budget_conflict,guests_conflict,quietness_evidence,child_age,cancellation; не придумывай новые имена. Для каждой values-записи evidence содержит дословный фрагмент запроса; country можно обосновать названием города. У search перечисли все обязательные поля в values; если они все заполнены из исходного текста, needs=[]. Дополнительные пожелания о бассейне, море, тишине сохраняются в backend как UNVERIFIED; не записывай их в needs и не утверждай, что свойства подтверждены. Точная фраза «с 26 по 28 октября 2026 года» означает checkin=2026-10-26 и checkout=2026-10-28. Если эти даты, город, гости, номера и бюджет уже однозначно заданы, не запрашивай их снова через clarify. Если обязательного поля не хватает, используй clarify с его названием в needs. Предпочтение не равно подтверждённому свойству.

Критерий завершения: Объект проходит schema, evidence и предметный валидатор.
\n\nОбязательный контракт нового поиска: intent=search допустим, только когда values содержит ВСЕ семь полей city,country,checkin,checkout,rooms,budget,currency. Бюджет и валюта обязательны наравне с датами и гостями; не опускай их как необязательные фильтры. Бери их из request_text, включая уже объединённый черновик. Например, «бюджет 30000 рублей» означает budget="30000", currency="RUB", evidence для обоих полей — дословная цитата этой фразы. Если явных данных не хватает, intent=clarify, values={}, evidence={}, needs содержит только отсутствующие обязательные поля. Не придумывай бюджет, валюту, даты или гостей. Если все семь полей присутствуют явно, верни search с полным values и needs=[]; повторное уточнение заполненного поля запрещено.\n

Backend передаёт input_observations: только явно разобранные условия request_text, включая проверенное соответствие города и страны. Используй эти наблюдения, чтобы не спрашивать уже заданный город повторно. Для complete-search схема разрешает только search с семью обязательными полями. Проверяй цитаты по request_text; наблюдения не разрешают придумывать отсутствующие поля. Для даты evidence допускает отдельную полную дату DD.MM.YYYY с предлогом с/по, ISO-дату или полный диапазон. При current_request!=null изменяй только запрошенные поля.
