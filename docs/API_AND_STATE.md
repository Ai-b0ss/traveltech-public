# HTTP, состояние и хранилище TravelTech

Срез `main` на 24.10.2026. Это рабочая карта для разработчиков, не обещание стабильного публичного API. Точные поля и ограничения проверяются по `experimental/full_server.py`.

## Основные маршруты

| Путь | Назначение |
|---|---|
| `/api/language` | Разбор текста, уточнение и Preview |
| `/api/skills/agent` | Расширенный агент с проверяемым структурированным предложением |
| `/api/full/agent` | Отдельный расширенный путь только при `--real` |
| `/api/commit` | Подтверждение Preview (`sid`, `preview_id`, `revision`) |
| `/api/action` | Локальная операция с состоянием и проверкой владельца |
| `/api/session`, `/api/preview` | Чтение принадлежащих клиенту объектов |
| `/api/request/status` | Состояние конкретной HTTP-операции и восстановление |
| `/api/session/revoke` | Отзыв клиентского nonce |
| `/api/data/search` | Read-only поиск для подтверждённой поездки, только с `--real` |
| `/api/data/select`, `/api/data/accept_quote` | Работа со снимком и выбором тарифа, не бронирование |
| `/api/data/location`, `/api/data/geo`, `/api/data/weather` | Другие внешние наблюдения, только при разрешённой внешней работе |

Наличие обработчика не гарантирует доступность провайдера в конкретном режиме.

## Карточка полного маршрута: backend-источник (26.10.2026)

Основной UI открывает учебную карточку только через `GET /api/trip_plan/demo`
без параметров. Кнопка «Открыть учебный маршрут · MOCK» получает ответ backend,
проверенный `demo_trip_plan()`. Локальный `/trip_plan_demo.json` больше не является
источником контроллера; при ошибке API автоматической подмены файлом нет.
Статический файл и автономный прототип оставлены для совместимости.

Демо остаётся `FIXED_MOCK_DEMO`, даже если совпадают даты, гости, назначение,
валюта и ревизия. Его отправление и бюджет не подтверждают условия пользователя;
UI явно пишет «не персональный расчёт» и не обещает соответствия лимиту.
Несовпадение проверяемых условий отклоняется. После подтверждённого изменения
условий прежние цены скрываются (STALE); повторный GET возвращает прежний MOCK
и не обновляет тарифы для новой ревизии.

В базе `39d897caab2c3fd42b11add718f27c391f154a54` команда уже добавила
`POST /api/trip_plan/session` с `sid` и `expected_revision`, проверками владельца
и ревизии. Это отдельный источник. Для персонального плана UI проверяет также
отправление и бюджет (сумма, валюта, область). Неизвестные условия дают
`NEEDS_INPUT` / `TRIP_PLAN_CONTEXT_UNKNOWN`, а не подходящий маршрут с вымышленной
ценой. Демо-корзина/заказ из main остаются только учебными действиями.

Проверки этого изменения: исторический отчёт 26.10 (в рабочем репозитории).

Оформление основного UI обновлено по запросу дизайнера: параметры раскрываются
через «Все условия», сессионный источник — через «Другой источник». На телефоне
та же форма диалога перемещается в закреплённую нижнюю панель после создания
сессии; при расширении экрана возвращается в боковую колонку. Обработчики формы,
Preview/commit, `sid`, ревизия и JSON-контракт от этого не меняются.

## История: локальный этап #48 (25.10.2026)

Основная страница загружает `/trip_plan_card.js`, `/trip_plan_card.css` и
`/trip_plan_ui.js`. По явной кнопке «Открыть локальный MOCK» читается статический
`GET /trip_plan_demo.json`: точный файл `docs/contracts/trip_plan_v0.json`.
Это учебный маршрут, не API поиска или пересчёта; он не привязан к владельцу сессии.

Кнопка серверного источника обращается к `GET /api/trip_plan/demo`, опубликованному
Игорем в ветке `feat/issue-44-trip-plan` (commit `e82577d32468c1f9e35afe8bde8b9698728b5ff7`).
В базе этого изменения (`6409a8eb049677092f540839623947522cb5b206`) обработчика нет;
здесь он не добавляется. Пока источник недоступен, UI показывает ошибку без
автоматической подмены локальными данными. Опубликованный демо-обработчик тоже
возвращает фиксированный MOCK, а не пересчитанный план сессии.

UI проверяет ревизию, направление, даты, валюту и состав гостей перед показом.
Это защита от несовместимого демоплана, не серверная проверка владения TripPlan.
После подтверждения новых условий через существующий Preview → `/api/commit`
прежний план получает локальную пометку STALE, его цены и сравнение с бюджетом
скрываются. JSON-контракт не меняется; `stale` — только параметр рендера.
Отмена Preview сохраняет прежние условия. Новый ответ старой ревизии отклоняется.

Пересчёт по сессии, набор вариантов, snapshot-корзина и имитация заказа ещё не
подключены. Подробности проверки и ограничения: исторический отчёт #48 (в рабочем репозитории).

## Переходы состояния

```text
Сообщение / форма
  → предложенные поля
  → уточнение или Preview (ожидает подтверждения)
  → /api/commit
  → подтверждённая поездка (sid + revision)
  → read-only поиск
  → снимок предложений с привязкой к владельцу и версии
  → сравнение и явный выбор
```

`draft_id` объединяет уточнения черновика, `preview_id` идентифицирует конкретное предложение, `sid` обозначает подтверждённую сессию, `revision` предотвращает применение устаревших изменений. Это разные идентификаторы. Любое изменение исходных условий требует переоценить применимость прежних результатов.

## Где находится доверенная логика

`FullHandler` контролирует Host/Origin, nonce, поле запроса и принадлежность ресурсов клиенту; `app.Application` и доменные валидаторы отвечают за данные поездки. Модель и поставщик не получают прав на изменение состояния.

`action_http_atomic` и `commit_http_atomic` записывают подтверждённые локальные изменения и HTTP-квитанцию в одной SQLite-транзакции. Это правило **не** доказывает отсутствие эффекта у уже отправленного внешнего обращения. При обрыве сначала проверяется статус операции и журнал; слепые повторы недопустимы.

## SQLite и источники

SQLite используется для поездок, черновиков, квитанций HTTP, nonce, учётных областей модельных запросов и снимков результатов. Это локальное runtime-состояние, не файлы для GitHub. Переход на PostgreSQL не реализован.

`supplier_router.py` передаёт гостиничные обращения `supplier_liteapi.py`, где проверяются структура ответа, валюта, идентификаторы отеля и распределение номеров. LiteAPI sandbox — тестовые предложения, не подтверждённое наличие. `offer_sort.js` допускает корректное сравнение сумм одной валюты или проверенный FX, а не произвольное межвалютное упорядочивание.

Новый Java/Spring Boot API или планировщик поездки с активностями могут быть будущими задачами, но в текущей системе их нет. См. [ARCHITECTURE.md](ARCHITECTURE.md), описание маршрутизации в рабочем репозитории и [CODE_GUIDE.md](CODE_GUIDE.md).

## Локальные уточнения условий (26.10.2026)

На `/api/language` с `mode=local` и Skills с `provider=Local` внешнее
геокодирование запрещено на всё время обработки, включая сборку черновика и
повторную проверку полей. Политика хранится в `ContextVar` и восстанавливается
после обработки; параллельные запросы не меняют настройки друг друга.
Неизвестный или неоднозначный город требует уточнения. Для явно указанного
известного города без локального архива Skills возвращает пустую выдачу с
`SOURCE_NOT_REQUESTED`, позволяя сохранить условия через Preview → Confirm.
Это не наблюдение цены или наличия.

«Добавь ребёнка 7 лет» сохраняет прежних детей и добавляет нового, включая
одинаковые возраста. Замена состава и «без детей» остаются отдельными правками;
неполный возраст и противоречащие инструкции требуют уточнения. Перенос
существующей поездки на два дня позже использует подтверждённые даты, сохраняет
прочие условия и создаёт Preview; после Confirm старые цены остаются STALE.
Общий бюджет поездки не заменяет бюджет гостиничного Request: нужна отдельная
сумма на отель. Контракт Request и фиксированный MOCK TripPlan не расширены.

Предложения направлений для запроса «к морю, без долгого переезда, бюджет
ограничен» остаются MOCK: цена, погода, валюта и длительность дороги неизвестны,
поездка не создаётся автоматически. Локальная регрессия воспроизводится через
`python -B -X utf8 scripts/qa_refinements_20261026.py --suite unit`
(также `--suite browser` и `--suite smoke`).
