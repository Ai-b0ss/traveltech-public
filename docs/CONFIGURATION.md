# Настройка TravelTech

Приложение имеет **автономный** режим и режим **LiteAPI sandbox**. Оба предназначены для разработки, а не для реальных бронирований.

## Без ключей: первый запуск

Установите Python 3.13. В корне проекта:

```bash
python -X utf8 experimental/full_server.py --port 8000
```

Откройте `http://127.0.0.1:8000`. В этом режиме можно изучать интерфейс и подтверждение поездки, но не проверять доступные сейчас номера и тарифы.

Проверить сервер без внешнего API:

```bash
python -X utf8 experimental/full_server.py --port 8833 --smoke
```

## Тестовый поиск LiteAPI

Только для разработчиков с **собственным разрешённым sandbox-ключом**. Пример PowerShell:

```powershell
$env:TRAVELTECH_MVP_DETERMINISTIC = "1"
$env:SUPPLIER_PROVIDER = "LITEAPI"
$env:LITEAPI_ENVIRONMENT = "sandbox"
$env:LITEAPI_KEY = "YOUR_OWN_LITEAPI_KEY"
python -X utf8 experimental/full_server.py --real --port 8000
```

Ключ запрашивается у владельца **в защищённом канале**, не через GitHub. Переменные задаются в текущем терминале — автоматическую загрузку `.env` не следует предполагать.

**Выбор поставщика по умолчанию:** если в `~/.traveltech-secrets/hotel_keys.json` уже есть разрешённый `sandbox_key` (или задан `LITEAPI_KEY`), TravelTech выбирает **LiteAPI** даже без `SUPPLIER_PROVIDER=LITEAPI`. Гражданство гостя при этом **не подставляется автоматически** — оно выбирается в интерфейсе для конкретного запроса. Без LiteAPI-ключа используется TourMind; явное `SUPPLIER_PROVIDER=TOURMIND` сохраняет возможность выбрать его вручную. Для испытаний без бронирований оставляйте `LITEAPI_ENVIRONMENT=sandbox`.

| Переменная | Назначение |
| --- | --- |
| `TRAVELTECH_MVP_DETERMINISTIC=1` | Базовый разбор без внешней модели |
| `SUPPLIER_PROVIDER=LITEAPI` | Основной поставщик |
| `LITEAPI_ENVIRONMENT=sandbox` | Только тестовые тарифы |
| `LITEAPI_KEY` | Секрет LiteAPI, **не для Git** |
| `LITEAPI_KEYS_FILE` | Альтернативный путь к файлу секретов **вне** репозитория |
| `SUPPLIER_FALLBACK` | Исторический резерв; не включать автоматически без проверки |
| `TRAVELTECH_PREVIEW_HOST` | Точное разрешённое имя временного HTTPS-стенда (без схемы); включает обязательную браузерную Basic-аутентификацию для **всех** запросов |
| `TRAVELTECH_PREVIEW_AUTH_HASH_FILE` | Путь к SHA-256 хешу пароля предпросмотра; по умолчанию `~/.traveltech-secrets/preview_basic.sha256`, вне Git |

В реальном режиме перед поиском выберите гражданство гостя. Для LiteAPI `/api/skills/agent` с `source_mode=live` и отсутствующим гражданством возвращает `GUEST_NATIONALITY_REQUIRED` **до запроса к модели** (без резерва HTTP-запроса). Read-only поиск sandbox создаёт **Preview без подтверждения** и без бронирования. Подтверждение Preview требуется только для сохранения поездки, а не для просмотра тестовых тарифов.

Сквозная проверка реального HTTP-пути, Gemini 4 Argon, LiteAPI sandbox и повторной доставки одного `X-Request-ID`: `python scripts/probe_gwarden_http_liteapi.py`. Выполнять лишь при подтверждённой актуальной бесплатной акции Gwarden; скрипт временно разрешает Gemini на 1 час **только в собственном процессе**, использует изолированную временную базу и не меняет публичный сервер.

## Проверки

```bash
python -m pip install -r requirements-dev.txt
python scripts/check_local.py
```

Полный прогон: `python scripts/check_local.py --suite full`. Браузерный: `python scripts/check_local.py --suite browser`. Часть проверок использует Microsoft Edge. Если Edge ещё не установлен, настрой его отдельно и установи браузерные компоненты Playwright.

Для проверки JavaScript нужен Node.js. Если его нет, локальный скрипт явно сообщает, что соответствующая проверка была пропущена.

## Не путать с production

Туннель `trycloudflare.com` временный и зависит от включённого компьютера. Не публикуйте порт Python напрямую в Интернет. Публичный хост требует TLS, строгого Host/Origin, изоляции пользователей, контроля секретов, ограничений и аудита. HTTP 200 страницы **не доказывает** успешный поиск гостиниц.

Локальный `audit/serve_local_rc38.py` содержит пути, специфичные для компьютера автора, и не предназначен для настройки новых участников.

Читайте [SECURITY.md](../SECURITY.md), [RELEASE_GATE.md](RELEASE_GATE.md) и [TEAM_START.md](TEAM_START.md).

## Режимы и фактическая маршрутизация (20.10.2026)

Без `--real` доступен локальный сценарий, но внешние `/api/data/*` отключены. `--real` открывает путь к внешним read-only обращениям, однако не гарантирует наличие ключа LiteAPI, рабочей модели или полномочий на другой API. Для sandbox-поиска требуются отдельная конфигурация, тестовый ключ и гражданство гостя.

`/api/language` в локальном режиме и `/api/skills/agent` в режиме внешней модели — разные пути интерпретации; их нужно проверять отдельно. В ветке PR #28 текущий `task_routing.PRIORITY` использует **Gwarden Gemini 4 Argon → InkStone** при действующем временном подтверждении промоакции; иначе `LEGACY_PRIORITY` — **IISHKO/DeepSeek → InkStone**. OmniRush из этого Auto-маршрута удалён. Перед демонстрацией обязательно проверить `/api/config` и реальный маршрут запущенного сервера. [AI_ROUTING.md](AI_ROUTING.md).

Контракты сессий, API и SQLite: [API_AND_STATE.md](API_AND_STATE.md). Указатель документов: [README.md](README.md).

## Модельные провайдеры с 21.10.2026

Базовая цепочка Auto **без временного разрешения Gemini** использует IISHKO и бесплатную InkStone Agents-A1; в PR #28 с временным разрешением первична Gemini 4 Argon через Gwarden. OmniRush и Logicc исключены из рабочего Auto-маршрута. Для первого командного запуска используется зашифрованный `team-access.enc`; ключи устанавливаются в `~/.traveltech-secrets`. Наличие ключа не означает гарантированную генерацию, бесплатность или гостиничную выдачу. [AI_ROUTING.md](AI_ROUTING.md).

## Закрытый HTTPS-предпросмотр: обязательный пароль

Указание `TRAVELTECH_PREVIEW_HOST` включает дополнительную HTTP Basic-защиту
перед выдачей nonce в `GET /api/config`, перед чтением HTML/JS и перед
любым POST. Это защищает **закрытый** предпросмотр при случайном раскрытии
адреса туннеля. Без корректного файла хеша сервер отвечает 403 (fail-closed);
без пароля или с неверным — 401 и `WWW-Authenticate`, чтобы браузер
попросил учётные данные. Даже заголовок `Host: localhost` не отменяет
этот пароль, когда внешний предпросмотр настроен. Локальный запуск без
`TRAVELTECH_PREVIEW_HOST` остаётся без Basic-защиты, как раньше.

На **своём локальном терминале** (не через удалённый вывод логов), один раз:

```powershell
python scripts/configure_preview_password.py
```

Скрипт генерирует 256-битный случайный пароль для пользователя `traveltech`,
показывает его один раз в терминале и сохраняет **только хеш** в
`~/.traveltech-secrets/preview_basic.sha256`. Сохраните пароль в менеджере
паролей; не отправляйте его в чат, GitHub, логи и командные аргументы.
Повторное выполнение не перезаписывает имеющийся файл. Для плановой
ротации сначала отключите туннель, замените учётные данные в приватном
хранилище и перенастройте клиенты.

Укажите `TRAVELTECH_PREVIEW_HOST` точно как HTTPS-хост, который передаёт
заголовок `Host` на локальный сервер (без `https://`). Туннель должен
предоставлять HTTPS с корректной проверкой сертификата, а backend должен
оставаться на `127.0.0.1`. Нельзя считать неподтверждённый пароль в
браузере разрешением публичного production.

**Важно:** пароль общий для закрытого предпросмотра, он не является
полноценной аутентификацией отдельных пользователей. Для публичного
многопользовательского сервиса нужны независимо проверенные пользователи,
контроль доступа перед выдачей nonce, rate limiting, аудит и изоляция
данных. Без этого — NO-GO. При использовании общего пароля сам браузер
сохраняет его в памяти авторизации; завершение предпросмотра требует
отключить туннель или сменить пароль.
