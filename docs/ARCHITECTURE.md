# Архитектура TravelTech

Актуальный срез `main` на 24 октября 2026 года, с дополнением от 25 октября 2026 года (см. раздел «Дополнение от 25 октября»). Здесь описан фактический код, а не обещания будущего хакатонного продукта.

## Состав и два пути обработки текста

TravelTech сейчас — Python 3.13, SQLite и интерфейс на HTML/CSS/JavaScript. Есть текстовое описание поездки, ручная форма, проверяемый предпросмотр и read-only поиск гостиниц. Бронирования и оплата не реализованы. Java/Spring Boot или PostgreSQL не являются частью текущего запуска.

**Локальный MVP** использует `/api/language` → `natural_language.py`, `refinement.py`, `city_names.py` и при необходимости `geo_city_resolver.py`. Он хорошо воспроизводим, но не гарантирует понимание произвольной речи.

**Расширенный Skills-путь** использует `/api/skills/agent` → `skill_system/runtime.py` → `registry.py` и `trust_boundary.py` → модельный transport → `contracts.py`, `backend.py` и `answer_grounding.py`. Проверенное структурированное предложение затем поступает в тот же доменный слой. Offline-вариант использует локальный транспорт; внешние модели доступны лишь при специальном запуске с `--real` и действующей конфигурации.

```text
Браузер: index.html / ui.js / full.js
    ├─ обычный текст и форма → /api/language → local_rules / refinement
    │                                       └─ cities / geocoder
    └─ расширенный агент   → /api/skills/agent → SkillAgent
                                            └─ контракты и проверки
                       │
                       ▼
              Preview: предложенные изменения
                       │ явное подтверждение
                       ▼
                /api/commit → app.Application → SQLite
                       │
                       ▼
                /api/data/search → supplier_router
                                         └─ supplier_liteapi (sandbox)
                       │
                       ▼
                снимок результатов → full.js / ui.js / offer_sort.js
```

Это схема логических связей, не полный call graph каждого HTTP-обработчика. API, идентификаторы и транзакции: [API_AND_STATE.md](API_AND_STATE.md).

## Границы модулей

- **UI:** `experimental/index.html`, `ui.js`, `full.js`, `style.css`, `full.css`, `offer_sort.js`. Отвечает за чат, ручную форму, Preview, карточки, сравнение. Не принимает решений о тарифах и не совершает броней.
- **HTTP:** `experimental/full_server.py`, `request_journal.py`. Проверяет поля, Host/Origin, nonce, принадлежность объектов, лимиты и идемпотентность.
- **Домен:** `experimental/app.py`, `prototype/base/`, `live_snapshot_store.py`. Проверяет поездку, создаёт черновики и Preview, подтверждает, хранит версии, результаты и откаты.
- **NLU:** `natural_language.py`, `refinement.py`, `city_names.py`, `geo_city_resolver.py`. Выделяет явные ограничения и спрашивает недостающие. Геокодер Open-Meteo подтверждает только подходящие однозначные названия.
- **Skills и модели:** `experimental/skill_system/`. Содержит агента, контракты, валидацию, маршруты и журналы. Документация по маршрутизации моделей в рабочем репозитории описывает условный порядок Gemini/InkStone и резерв IISHKO/InkStone.
- **Источники:** `supplier_router.py`, `supplier_liteapi.py`, `live_data.py`. Основной проверенный гостиничный маршрут в MVP — LiteAPI sandbox; адаптеры Pilot/transfer/enrichment от 25.10 — изолированные opt-in модули, не подключённые к основному маршруту (см. дополнение от 25 октября).

## Инварианты поведения

1. Модель предлагает значения, но не создаёт подтверждённую поездку и не является источником сведений о тарифах. Сервер и доменные валидаторы проверяют даты, валюты, гостей, комнаты и бюджет.
2. Пропуски и противоречия уточняются. Для одного явно указанного взрослого одна комната может быть предложена по умолчанию лишь как видимое редактируемое значение в Preview.
3. Сохранение изменений — после подтверждения. `draft_id`, `preview_id`, `sid` и `revision` отвечают за разные состояния и не взаимозаменяемы.
4. Локальные изменения и HTTP-квитанция для атомарных операций фиксируются одной SQLite-транзакцией. Неизвестный результат внешнего запроса нельзя считать отсутствием эффекта и слепо повторять.
5. Изменение условий поездки может сделать старые тарифы и сравнение недействительными. Снимки результатов привязаны к владельцу, поездке и ревизии.
6. Тестовый тариф LiteAPI не равен гарантированной цене, доступности или брони. Данные о налогах, отмене, отзывах, тишине и курсах валют требуют источника.

## UI, сортировка и релиз

Чат на первом экране, формы и инженерные настройки доступны отдельно. Состояние CSS не подменяет подтверждение на сервере. `offer_sort.js` обеспечивает общую сортировку тарифов; сравнение разных валют без проверенного пересчёта запрещено.

Скрипт `scripts/check_local.py` выполняет локальные проверки. GitHub Actions не обязательны. Важно самостоятельно проверить изменённый сценарий в браузере и отдельно LiteAPI sandbox. [CONFIGURATION.md](CONFIGURATION.md) и [README.md](../README.md) содержат команды.

Никакой полноценный маршрут с активностями, Java-сервис, бронирование, платежи или production-многопользовательский стенд не считаются реализованными. Исторические `audit/`, `research/`, `vendor/` и датированные UX/AI-отчёты не определяют текущую архитектуру. Начните с [указателя документов](README.md).
